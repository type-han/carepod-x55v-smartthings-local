# 4. 안전 수칙과 되돌리기

## 4-1. 보내면 안 되는 값

실제로 보내 보고 확인한 값입니다. 드라이버는 이 값들을 보내지 않도록 막아 두었습니다 (`carepod.is_safe`).
브로커에서 직접 명령을 보낼 때는 **반드시** 지켜 주세요.

| path | 위험한 값 | 증상 |
|---|---|---|
| `mist.step` | **0** | 꺼지고, 그 뒤로 전원 버튼이 제대로 동작하지 않음 |
| `mist.step` | **4** | 꺼지고 먹통이 됨. 취침 모드에서 기기가 스스로 4로 바꾸므로 **읽기 전용** |
| `mist.target_humidity` | 40/45/50/55/60 **외의 값** | 고장을 일으킴 |

- 전원을 끌 때는 `mist.step 0`이 아니라 **`power 0`** 을 씁니다.
- 위 표에 없는 path(`drain`, `fan` 등)는 시험하지 않았습니다. 모르는 path나 값은 보내지 마세요.
- 기기가 먹통이 되면 전원 플러그를 뽑았다가 다시 꽂아 보세요.

## 4-2. 보안

- 로컬 브로커는 **익명 접속을 허용**하고 가습기의 비밀번호도 검사하지 않습니다. LAN 안의 누구나 명령을 보낼 수 있습니다.
  - 브로커 포트(1883)를 인터넷에 열지 마세요 (공유기 포트포워딩 금지).
  - 게스트 WiFi나 신뢰하지 않는 기기를 같은 LAN에 두지 마세요.
- 직접 캡처한 pcap 파일에는 **가습기의 MQTT 비밀번호가 평문**으로 들어 있습니다. 이슈나 게시글에 올리지 마세요.
  `tools/mqtt_decode.py`는 기본으로 비밀번호를 가립니다.
- 다른 사람의 기기 토픽을 구독하거나 제조사 클라우드 브로커에 직접 접속하지 마세요. 이 프로젝트는 **본인 기기를 본인 LAN에서** 쓰기 위한 것입니다.

## 4-3. 클라우드로 되돌리기

CAREPOD 앱을 다시 쓰고 싶을 때.

**방법 A (리눅스 AP)**
```bash
# AP 서버
systemctl disable --now carepod-redirect carepod-ap
```
그다음 CAREPOD 앱에서 가습기를 **원래 집 WiFi로 다시 등록**합니다. 브로커는 꺼도 됩니다.

**방법 B (공유기 DNAT)**: 규칙을 지우고 가습기 전원을 껐다 켭니다.

**방법 C (DNS)**: DNS 재지정을 지우고 가습기 전원을 껐다 켭니다 (WiFi 재접속만으로는 예전 IP를 계속 씀).

SmartThings의 "CAREPOD 가습기" 기기는 삭제하면 됩니다.

## 4-4. 알아 둘 것

- 로컬 브로커에서는 펌웨어 OTA가 오지 않습니다. 업데이트가 필요하면 잠시 클라우드로 되돌리세요.
  업데이트 후에는 동작이 바뀔 수 있으니 (특히 TLS가 켜지면 이 방법은 막힙니다) 주의하세요.
- 방법 A에서 AP 서버가 꺼지면 가습기는 WiFi를 잃습니다. 본체 버튼으로는 계속 쓸 수 있습니다.
